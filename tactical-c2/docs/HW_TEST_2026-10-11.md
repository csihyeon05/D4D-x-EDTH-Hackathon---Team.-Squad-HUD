# Hardware test — NU40 commander gateway → backend → COP (2026-10-11)

Tested on the commander laptop (Windows), 01:00–01:45 KST. Goal: confirm that a soldier node's
radio packet reaches the website (COP) through the Operator (gateway) board.

## Result

**End-to-end path works:** soldier node (BLE advertisement) → NU40 gateway (USB serial) → backend
(`C2_SOURCE=serial`) → COP shows soldier **S2** in sector **A1**.

## 1. Operator (gateway) board

| Item | Value |
|---|---|
| Board (USB descriptor) | `NU40DK nRF52840`, USB VID `0x239A` |
| Port before flashing | COM8 (PID `0x80AC`), old firmware |
| Old firmware output | `{"event":"status","connected":0,"receiving":0}` every ~2.7 s. Not found on any branch; looks like an old NUS connection client. **Not compatible** with the backend. |
| Flashed firmware | `firmware` branch `f79cf2e`, `firmware/nu40-commander` (env `nu40_commander`). Identical to `codex/soldier-sensor-integration:firmware/nu40-commander`. |
| Build | PlatformIO 6.2.0, nordicnrf52@11.0.0. Flash 124,480 B, RAM 27,904 B |
| Bootloader | Auto-reset (1200 bps touch) **did not work**: upload hung at "Using manually specified: COM8". Fixed by **double-pressing RESET** → bootloader appeared as COM9 (PID `0x00DA`) + USB drive, then flashed with `adafruit-nrfutil dfu serial -p COM9 --singlebank` (7.8 s). |
| Port after flashing | **COM10** (PID `0x8029`) — the COM number changes after flashing, check it. |

Gateway output after flashing (115200 baud), matches its README:

```
GW,uptime_s=71,adverts=34132,forwarded=0,duplicates=0,queue_drops=0,expired=1
...
PKT:1202ab7650060000a408070000000000007d,RSSI:-69
GW,uptime_s=374,adverts=181109,forwarded=1,duplicates=5,queue_drops=0,expired=11
```

- `adverts` ≈ 490/s: passive scan works (crowded venue, ~300 BLE devices nearby).
- `forwarded=1, duplicates=5`: one soldier packet, its burst repeats suppressed as designed.
- `expired` counts valid packets that arrived while no program had the port open (dropped after 5 s, by design).

## 2. Received soldier packet

Decoded with `backend/app/protocol.py` (`parse_gateway_line`):

| Field | Value |
|---|---|
| type | 2 = CHECKIN |
| soldier_id | **2** |
| seq | 30379 |
| t_s | 1616 s since node power-on |
| code | 0 (none) |
| hr_bpm | 0 = no reading (pulse sensor probably disabled, `CFG_PULSE=0`) |
| skin_temp | 22.12 °C (room temperature → TMP36 not touching skin) |
| activity | 7 |
| x, y | 0, 0 (PDR origin) |
| gas, hops | 0, 0 |
| RSSI | −69 dBm |

So a node running the **advertisement protocol** (`soldier-firmware`, 18-byte packet, company ID
`0xFFFF`) was on air with `SOLDIER_ID=2`.

## 3. Backend + website

- `tactical-c2/backend` started with `C2_SOURCE=serial C2_SERIAL_PORT=COM10 C2_SERIAL_BAUD=115200`
  (`tools/hw/run_backend_serial.ps1`).
- `/api/state`: `S2, OK, skin_temp_c 22.1, activity 7, sector A1, rssi -67, checkins 1`.
- COP page: S2 marker in A1, card `S2 · OK · ♥ 0 · 22.7° · PSI 0.2`, alert log 0.

## 4. Issues found — action needed

1. **Firmware versions on the `firmware` branch do not match each other.**
   `firmware/nu40-commander` (gateway) expects the 18-byte advertisement, but
   `firmware/nucode-project*` (soldier) still use NUS (BLE connection + JSON). A soldier board
   flashed from `firmware/nucode-project` will **never** be seen by this gateway.
   → Flash soldier boards from **`codex/soldier-sensor-integration:soldier-firmware`** (advertisement
   protocol v1, same `gateway_core` as the gateway), e.g.
   `SOLDIER_ID=2 IMU_MODEL=lsm6ds3 CFG_PULSE=0 CFG_GPS=0 sh tools/nu87.sh upload <port>`.
   Give each board its own `SOLDIER_ID`.
2. **`hr_bpm=0` shown as ♥ 0 and used for PSI.** This `tactical-c2` backend treats 0 as a value.
   `commander-hq` on `codex/soldier-sensor-integration` already maps 0 → null. Use `commander-hq`
   for the demo, or port that fix.
3. **Temperature 22 °C** → mount the TMP36 against skin, otherwise PSI/heat rules are meaningless.
4. **Check-in only every 120 ± 30 s.** When testing, wait up to ~150 s, or trigger an alert
   (fall + stay still ≥ 10 s), before concluding that nothing is received.
5. Only one program may open the gateway port. Close serial monitors before starting the backend.

## 5. Checklist for the soldier-firmware PC

- [ ] Soldier board firmware = `soldier-firmware` (advertisement), not `firmware/nucode-project` (NUS)
- [ ] `SOLDIER_ID` set and unique; IMU model / `CFG_PULSE` / `CFG_TMP36` match the fitted sensors

## Tools added (`tactical-c2/tools/hw/`)

| File | Purpose |
|---|---|
| `flash_nu40_gateway.ps1` | Clone `firmware` branch, install PlatformIO in a venv, build and flash the gateway (handles the RESET-double-press bootloader path) |
| `read_serial.ps1` | Read any COM port for N seconds without writing to it |
| `run_backend_serial.ps1` | Start the backend in serial mode on a given COM port |
| `ble_scan.py` | PC Bluetooth scan for NU nodes / NUS service / company ID `0xFFFF` adverts |
| `decode_pkt.py` | Decode a `PKT:` line with the backend parser |
